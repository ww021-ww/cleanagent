# 漏洞清洗智能体技术文档

## 项目概述

本项目构建了一个基于 **LangGraph 状态机**驱动的多源漏洞情报治理系统，实现了从数据抽取到存储的完整智能化流水线。系统采用"离线处理 + 在线服务"的一体化架构，通过 **Extract → Clean/Validate → Store** 的状态机流程，统一处理 CVE/NVD/CNVD/CISA/CERT/JVN 六类异构漏洞数据源。

**核心特点：**
- **状态机架构**：使用 LangGraph 管理复杂的数据处理流程
- **智能化处理**：结合规则解析和 LLM 补全的混合策略
- **质量驱动路由**：基于数据质量评分的条件分支
- **异步高并发**：支持大规模文件的并发处理

## 2. LangGraph & LangChain 技术深度解析

### 2.1 LangGraph 技术选型与架构设计

#### 2.1.1 LangGraph 核心概念与优势

**LangGraph 是什么？**
LangGraph 是 LangChain 生态系统中的状态图编排框架，专门用于构建复杂的多步骤 AI 应用。它将传统的链式调用转换为有向无环图（DAG），支持条件分支、循环和状态管理。

**核心优势分析：**

1. **状态持久化管理**
   - 每个节点都可以读取和修改全局状态
   - 支持复杂的数据流转和状态追踪
   - 便于调试和监控处理过程

2. **条件路由与分支控制**
   - 支持基于状态的动态路由决策
   - 可以实现复杂的业务逻辑分支
   - 避免了传统链式调用的线性限制

3. **可观测性与调试能力**
   - 每个节点的执行状态都可以被追踪
   - 支持中间状态的检查和调试
   - 便于性能分析和问题定位

4. **异常处理与容错机制**
   - 内置的错误处理和重试机制
   - 支持节点级别的异常隔离
   - 可以实现优雅的降级策略

#### 2.1.2 技术选型对比分析

**LangGraph vs 传统工作流引擎**

| 对比维度 | LangGraph | Apache Airflow | Prefect | Temporal |
|---------|-----------|----------------|---------|----------|
| **AI集成** | 原生支持LLM调用 | 需要额外集成 | 需要额外集成 | 需要额外集成 |
| **状态管理** | TypedDict状态共享 | XCom传递 | 结果缓存 | 工作流状态 |
| **条件路由** | 基于状态的智能路由 | 分支操作符 | 条件任务 | 工作流决策 |
| **开发复杂度** | 简单，Python原生 | 复杂，需要DAG定义 | 中等，装饰器模式 | 复杂，需要工作流定义 |
| **部署复杂度** | 轻量级，单进程 | 重量级，需要调度器 | 中等，需要服务端 | 重量级，分布式架构 |
| **实时性** | 支持同步/异步 | 批处理为主 | 支持实时 | 支持实时 |
| **学习成本** | 低，基于LangChain | 高，需要学习调度概念 | 中等 | 高，需要学习分布式概念 |

**选择LangGraph的核心理由：**

1. **AI-First设计**：专为LLM应用设计，无需额外的AI集成工作
2. **轻量级部署**：单进程运行，无需复杂的分布式架构
3. **开发效率**：基于Python类型提示，开发体验友好
4. **状态透明**：所有中间状态都可见，便于调试和监控

LangChain 是一个用于开发由语言模型驱动的应用程序的框架。它提供了标准化的接口、模块化的组件和端到端的链式调用，简化了LLM应用的开发过程。

class CleanerValidatorAgent:
    def validate(self, data: Dict, source: str) -> Dict:
        """实际的数据验证逻辑"""
        validation_result = {
            'is_valid': True,
            'errors': [],
            'warnings': [],
            'field_scores': {}
        }
        
        field_config = self.field_config_loader.get_source_config(source)
        
        for field_name, field_info in field_config['fields'].items():
            value = data.get(field_name)
            field_score = 1.0
            
            # 必需字段检查
            if field_info.get('required', False) and not value:
                validation_result['errors'].append(f"缺少必需字段: {field_name}")
                field_score = 0.0
            
            # 数据类型检查
            if value is not None:
                expected_type = field_info.get('type', 'str')
                if not self._validate_type(value, expected_type):
                    validation_result['warnings'].append(f"字段类型不匹配: {field_name}")
                    field_score *= 0.8
            
            validation_result['field_scores'][field_name] = field_score
        
        return validation_result

async def process_directory(self, directory: str, pattern: str = '*.html',
                           max_workers: int = 4, timeout: int = 3600) -> Dict[str, Any]:
    """
    目录级并发处理
    
    处理流程：
    1. 文件发现与过滤
    2. 预过滤已处理文件（避免重复处理）
    3. 并发控制（asyncio.Semaphore）
    4. 异常隔离与统计
    """
    self.stats['start_time'] = time.time()
    
    # 文件发现
    directory_path = Path(directory)
    files = list(directory_path.glob(pattern))
    logger.info(f"发现 {len(files)} 个文件")
    
    # 预过滤已处理文件
    unprocessed_files = await self._filter_unprocessed_files(files)
    logger.info(f"需要处理 {len(unprocessed_files)} 个文件")
    
    # 并发控制
    semaphore = asyncio.Semaphore(max_workers)
    
    async def process_with_limit(file_path: Path):
        """带并发限制的文件处理"""
        async with semaphore:
            return await self.process_file(str(file_path))
    
    # 并发执行
    results = await asyncio.gather(
        *[process_with_limit(f) for f in unprocessed_files], 
        return_exceptions=True
    )
    
    # 异常处理与统计
    for i, result in enumerate(results):
        if isinstance(result, Exception):
            logger.error(f"处理文件 {unprocessed_files[i]} 时发生异常: {result}")
            self.stats['failed'] += 1
    
    self.stats['end_time'] = time.time()
    return self.get_stats()

class JSONExtractor:
    def flatten_json(self, data: Dict, parent_key: str = '', sep: str = '_') -> Dict:
        """
        递归 JSON 扁平化：
        1. 嵌套对象展开为下划线分隔键
        2. 数组处理为索引键或合并字符串
        3. 保持数据类型完整性
        """
        items = []
        for k, v in data.items():
            new_key = f"{parent_key}{sep}{k}" if parent_key else k
            
            if isinstance(v, dict):
                items.extend(self.flatten_json(v, new_key, sep=sep).items())
            elif isinstance(v, list):
                if v and isinstance(v[0], dict):
                    # 对象数组：展开为索引键
                    for i, item in enumerate(v):
                        items.extend(self.flatten_json(item, f"{new_key}_{i}", sep=sep).items())
                else:
                    # 基础类型数组：合并为字符串
                    items.append((new_key, ', '.join(map(str, v))))
            else:
                items.append((new_key, v))
        
        return dict(items)
    
    def filter_by_whitelist(self, data: Dict, source: str) -> Dict:
        """
        字段白名单过滤：
        1. 基于配置的字段映射
        2. 必需字段验证
        3. 数据类型转换
        """
        field_config = self.field_config_loader.get_source_config(source)
        whitelist = field_config.get('fields', {}).keys()
        
        filtered_data = {}
        for field in whitelist:
            if field in data:
                # 数据类型转换

class DatabaseManager:
    def create_dynamic_model(self, source: str, table_type: str = 'main') -> Type:
        """
        动态 SQLAlchemy 模型生成：
        1. 读取 YAML 字段配置
        2. 生成对应的 SQLAlchemy 列
        3. 设置索引和约束
        4. 缓存模型类避免重复创建
        """
        cache_key = f"{source}_{table_type}"
        if cache_key in self.model_cache:
            return self.model_cache[cache_key]
        
        # 获取字段配置
        field_config = self.field_config_loader.get_source_config(source)
        fields = field_config.get('fields', {})
        
        # 构建列定义
        columns = {'__tablename__': f"{source.lower()}_{table_type}"}
        
        for field_name, field_info in fields.items():
            column_type = self._get_sqlalchemy_type(field_info.get('type', 'str'))
            nullable = not field_info.get('required', False)
            
            if field_info.get('primary_key'):
                columns[field_name] = Column(column_type, primary_key=True)
            elif field_info.get('unique'):
                columns[field_name] = Column(column_type, unique=True, nullable=nullable)
            else:
                columns[field_name] = Column(column_type, nullable=nullable)
        
        # 添加通用字段
        columns.update({
            'created_at': Column(DateTime, default=datetime.utcnow),
            'updated_at': Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
        })
        
        # 动态创建模型类
        model_class = type(f"{source.title()}{table_type.title()}Model", (Base,), columns)
        
        # 缓存模型
        self.model_cache[cache_key] = model_class
        
        return model_class

### 4.2 批量 Upsert 优化

**高性能批量操作**
```python
def bulk_upsert(self, data_list: List[Dict], source: str, 
                batch_size: int = 50) -> Dict[str, int]:
    """
    批量 Upsert 优化策略：
    1. 数据类型验证与转换
    2. 批量插入优先，失败时单条回退
    3. 冲突处理与更新
    4. 性能统计与监控
    """
    model_class = self.get_model(source)
    stats = {'inserted': 0, 'updated': 0, 'failed': 0}
    
    # 分批处理
    for i in range(0, len(data_list), batch_size):
        batch = data_list[i:i + batch_size]
        
        try:
            # 批量插入尝试
            validated_batch = [self._validate_data(item, source) for item in batch]
            
            # 使用 ON DUPLICATE KEY UPDATE
            stmt = insert(model_class).values(validated_batch)
            
            # MySQL 特定的 upsert 语法
            update_dict = {
                col.name: stmt.inserted[col.name] 
                for col in model_class.__table__.columns 
                if col.name not in ['id', 'created_at']
            }
            update_dict['updated_at'] = datetime.utcnow()
            
            stmt = stmt.on_duplicate_key_update(**update_dict)
            
            result = self.session.execute(stmt)
            self.session.commit()
            
            stats['inserted'] += len(batch)
            
        except Exception as e:
            self.session.rollback()
            logger.warning(f"批量插入失败，回退到单条处理: {e}")
            
            # 单条回退处理
            for item in batch:
                try:
                    single_stats = self.upsert(item, source)
                    for key in stats:
                        stats[key] += single_stats.get(key, 0)
                except Exception as single_error:
                    logger.error(f"单条插入失败: {single_error}")
                    stats['failed'] += 1
    
    return stats
```

### 4.3 去重与质量控制

**多层级去重机制**
```python
def check_duplicate(self, data: Dict, source: str) -> bool:
    """
    多维度去重检查：
    1. 主键去重（CVE ID、源 ID）
    2. 内容哈希去重
    3. 时间窗口去重
    """
    model_class = self.get_model(source)
    
    # 主键去重
    primary_keys = self._get_primary_keys(source)
    if primary_keys:
        query = self.session.query(model_class)
        for key in primary_keys:
            if key in data:
                query = query.filter(getattr(model_class, key) == data[key])
        
        if query.first():
            return True
    
    # 内容哈希去重
    content_hash = self._calculate_content_hash(data)
    existing = self.session.query(model_class).filter(
        model_class.content_hash == content_hash
    ).first()
    
    return existing is not None

def _calculate_content_hash(self, data: Dict) -> str:
    """计算内容哈希用于去重"""
    # 排除时间戳等变化字段
    stable_fields = {k: v for k, v in data.items() 
                    if k not in ['created_at', 'updated_at', 'id']}
    
    content_str = json.dumps(stable_fields, sort_keys=True, ensure_ascii=False)
    return hashlib.md5(content_str.encode()).hexdigest()
```

class VulnSearchService:
    def search_vulnerabilities(self, 
                             query: str = None,
                             sources: List[str] = None,
                             risk_levels: List[str] = None,
                             date_from: datetime = None,
                             date_to: datetime = None,
                             page: int = 1,
                             page_size: int = 20,
                             sort_by: str = 'updated_at',
                             sort_order: str = 'desc') -> Dict:
        """
        统一多源漏洞查询：
        1. 动态构建跨表查询
        2. 条件过滤与分页
        3. 结果标准化
        """
        # 获取所有可用数据源
        available_sources = sources or list(SOURCE_TABLE_MAP.keys())
        
        all_results = []
        total_count = 0
        
        for source in available_sources:
            # 获取源特定的表和字段映射
            table_info = SOURCE_TABLE_MAP.get(source)
            if not table_info:
                continue
            
            model_class = self.db_manager.get_model(source)
            
            # 构建查询
            query_builder = self.session.query(model_class)
            
            # 应用过滤条件
            if query:
                # 全文搜索
                search_fields = table_info.get('search_fields', ['title', 'description'])
                conditions = []
                for field in search_fields:
                    if hasattr(model_class, field):
                        conditions.append(
                            getattr(model_class, field).like(f'%{query}%')
                        )
                if conditions:
                    query_builder = query_builder.filter(or_(*conditions))
            
            if risk_levels:
                if hasattr(model_class, 'risk_level'):
                    query_builder = query_builder.filter(
                        model_class.risk_level.in_(risk_levels)
                    )
            
            if date_from:
                query_builder = query_builder.filter(
                    model_class.updated_at >= date_from
                )
            
            if date_to:
                query_builder = query_builder.filter(
                    model_class.updated_at <= date_to
                )
            
            # 统计总数
            source_count = query_builder.count()
            total_count += source_count
            
            # 排序
            if hasattr(model_class, sort_by):
                order_func = desc if sort_order == 'desc' else asc
                query_builder = query_builder.order_by(
                    order_func(getattr(model_class, sort_by))
                )
            
            # 分页（按源分配）
            source_limit = min(page_size, source_count)
            source_results = query_builder.limit(source_limit).all()
            
            # 结果标准化
            for result in source_results:
                standardized = self._standardize_result(result, source, table_info)
                all_results.append(standardized)
        
        # 全局排序和分页
        all_results.sort(key=lambda x: x.get(sort_by, ''), reverse=(sort_order == 'desc'))
        
        start_idx = (page - 1) * page_size
        end_idx = start_idx + page_size
        paginated_results = all_results[start_idx:end_idx]
        
        return {
            'items': paginated_results,
            'total': total_count,
            'page': page,
            'page_size': page_size,
            'total_pages': (total_count + page_size - 1) // page_size
        }

class PerformanceMonitor:
    def __init__(self):
        self.metrics = {
            'files_processed': 0,
            'processing_time': 0,
            'extraction_time': 0,
            'cleaning_time': 0,
            'storage_time': 0,
            'errors': 0
        }
    
    @contextmanager
    def time_operation(self, operation: str):
        """操作耗时监控"""
        start_time = time.time()
        try:
            yield
        finally:
            elapsed = time.time() - start_time

            'total_time': self.metrics['processing_time'],
            'avg_time_per_file': avg_processing_time,
            'success_rate': success_rate,
            'error_count': self.metrics['errors'],
            'throughput': self.metrics['files_processed'] / max(self.metrics['processing_time'], 1)

**实际应用效果：**

**Q4: 混合抽取策略是如何设计的？为什么选择LangChain？**

A: 我们采用"规则解析 + LLM补全"的混合策略：

**混合策略设计：**
- **规则解析优先**：使用BeautifulSoup和正则表达式进行结构化数据提取，效率高、成本低
- **LLM智能补全**：当规则解析无法获取关键字段时，调用GPT模型进行智能补全
- **置信度评估**：每种方法都会给出置信度分数，用于后续的质量评分
- **成本控制**：只有在必要时才调用LLM，避免不必要的API开销

**选择LangChain的原因：**
1. **统一的LLM接口**：支持OpenAI、Claude、本地模型等多种LLM，便于模型切换和A/B测试
2. **强大的Prompt工程**：提供PromptTemplate系统，支持动态参数注入和模板复用
3. **结构化输出解析**：PydanticOutputParser可以自动将LLM输出解析为结构化数据
4. **错误处理机制**：内置重试、降级等容错机制，提高系统稳定性

**与其他方案对比：**

- **vs LlamaIndex**：LangChain更适合通用的LLM应用开发，而LlamaIndex专注于RAG场景
- **vs Semantic Kernel**：LangChain的Python生态更成熟，社区支持更好

- 规则解析覆盖80%的常见字段，LLM补全处理20%的复杂情况
- 平均每个文件的LLM调用成本控制在0.01美元以内
- 数据完整性相比纯规则解析提升了30%
