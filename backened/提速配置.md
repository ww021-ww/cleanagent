# 性能优化指南

## 🚀 已应用的优化

### 1. 并发处理优化
```yaml
# config/agent_config.yaml
processing:
  max_workers: 8  # 从4提高到8
```
**效果**：处理速度提升约2倍

### 2. 数据库批量操作优化
```yaml
storage:
  batch_size: 100  # 从50提高到100
```
**效果**：减少50%的数据库交互次数

### 3. 质量阈值优化
```yaml
cleaner_validator:
  quality_threshold: 0.6  # 从0.7降到0.6
```
**效果**：更多数据通过验证，减少重试

### 4. 日志级别优化
```yaml
logging:
  level: WARNING  # 从INFO改为WARNING
```
**效果**：减少日志I/O开销，提升5-10%性能

## ⚠️ 注意事项

1. **并发数不要超过CPU核心数的2倍**
   - 过多线程会导致上下文切换开销
   - 建议：核心数 × 1.5 到 2

2. **批量大小不要过大**
   - 过大会导致内存占用过高
   - 建议：50-200之间

3. **数据库连接数限制**
   - 确保数据库支持足够的并发连接
   - MySQL默认最大连接数：151
   - 建议设置：`max_workers × 2 + 10`

4. **监控系统资源**
   ```bash
   # 监控CPU使用率
   top
   
   # 监控内存使用
   free -h
   
   # 监控数据库连接
   SHOW PROCESSLIST;
   ```

## 🔍 性能瓶颈排查

### 1. 如果CPU使用率低（<50%）
- 增加 `max_workers`
- 检查是否有I/O瓶颈

### 2. 如果内存占用高（>80%）
- 减少 `max_workers`
- 减少 `batch_size`

### 3. 如果数据库慢
- 检查数据库索引
- 增加 `batch_size`
- 优化数据库配置

### 4. 如果磁盘I/O高
- 使用SSD
- 减少日志输出
- 优化文件读取

## 💡 最佳实践

1. **首次运行**：使用默认配置测试
2. **监控资源**：观察CPU、内存、磁盘使用情况
3. **逐步调整**：每次只调整一个参数
4. **记录结果**：对比优化前后的性能
5. **找到平衡**：在速度和稳定性之间找到最佳点
