# 漏洞数据处理系统 - 完整处理流程

## 一、系统概览

本系统是基于 **LangGraph** 的多智能体漏洞数据处理系统，支持 6 个数据源（CVE、NVD、CNVD、CISA、CERT、JVN），通过状态机驱动单个文件（一个漏洞）从磁盘读入到数据库写入的全流程。

---

## 三、一个漏洞文件的完整处理流程（逐步详解）

### 第 0 步：启动与初始化

```
main.py
  │
  ├── 加载 config/agent_config.yaml
  ├── 加载 config/database.env（数据库连接 URI、API Key 等）
  ├── 初始化日志
  └── 创建 LangGraphController
            │
            └── build_vuln_processing_graph(config)
                      │
                      └── 编译 StateGraph（4 个节点 + 条件路由）
```

**关键配置文件：**

| 文件 | 作用 |
|------|------|
| `config/agent_config.yaml` | LLM 模型、质量阈值、并发数、超时等 |
| `config/database.env` | DB_URI、OPENAI_API_KEY 等 |
| `config/field_mappings.yaml` | 每个数据源的字段定义、表名、子表配置 |

---

### 第 1 步：文件扫描 + 批量预过滤

**位置：** `graph/controller.py` → `process_directory()`

```
1. rglob 扫描目录，收集所有 .json / .html 文件列表
2. 连接 MySQL，从所有数据源主表查出已存在的漏洞 ID 集合
   existing_ids = {CVE-2022-1030, CVE-2022-1031, ...}
3. 过滤：files = [f for f in files if f.stem not in existing_ids]
4. 记录跳过数量到统计信息
5. asyncio.Semaphore(max_workers) 控制并发，默认 4 个并发
```

> 例：扫到 15231 个文件，MySQL 已有 41 条，实际只处理 15190 个文件。

---

### 第 2 步：创建初始状态，进入 LangGraph

**位置：** `graph/controller.py` → `process_file()` → `graph/state.py`

```python
initial_state = VulnProcessingState(
    task_id   = uuid4(),
    file_path = "D:/notebook/cleanagent/json/cves/CVE-2022-1036.json",
    source    = None,
    extracted_data = None,
    quality_score  = 0.0,
    final_status   = 'pending',
    ... # 其余字段均为空/默认值
)
```

状态对象贯穿整个 LangGraph，每个节点读入状态、返回更新后的状态。

---

### 第 3 步：extract 节点 — 数据提取

**位置：** `graph/nodes.py` → `extract_node()` → `agent/extractor.py`

#### 3.1 兜底跳过检查（单文件调用保障）

```
用 file.stem（如 CVE-2022-1036）查 MySQL 主表
→ 已存在 → 直接返回 final_status='skipped'
→ 不存在 → 继续处理
```

#### 3.2 识别数据源

```
ExtractorAgent.identify_source(file_path, content)
  │
  ├── 路径关键词匹配：nvd/ → NVD，cves/ → CVE，cnvd/ → CNVD ...
  ├── 文件名前缀匹配：CVE- → CVE，CNVD- → CNVD，VU- → CERT ...
  └── 内容特征匹配：cveMetadata → CVE，containers.cna → CVE ...
```

#### 3.3 路由到对应提取器

根据识别出的 source，调用对应的 `SourceExtractor`：

```
文件内容
  │
  ├── JSON 文件
  │     ├── 含 vulnerabilities[] → CISA 多漏洞格式 → map_json_fields()
  │     ├── 含 cveMetadata / id  → CVE/NVD 格式   → JSONExtractor.extract()
  │     ├── CERT JSON            → extract_cert_json_file()
  │     └── 其他单漏洞 JSON      → map_json_fields()
  │
  └── HTML 文件
        ├── CNVD HTML  → BeautifulSoup 规则提取 + LLM 补充
        ├── CERT HTML  → extract_cert()
        ├── JVN HTML   → 专用 JVN 规则
        └── 其他 HTML  → 通用规则 + LLM
```

#### 3.4 JSONExtractor 详细流程（CVE/NVD 数据源）

**位置：** `agent/json_extractor.py`

```
JSONExtractor.extract(data)
  │
  ├── source == 'cve' → extract_cve(data)
  │     ├── 扁平化 cveMetadata.*
  │     ├── 扁平化 containers.cna.*（描述、影响产品、参考链接等）
  │     └── filter_fields() 过滤掉不在 field_mappings.yaml 的字段
  │
  └── source == 'nvd' → extract_nvd(data)
        ├── 扁平化顶层字段（id、published、lastModified 等）
        ├── 提取 descriptions[lang=en].value
        ├── 提取 weaknesses[].description[lang=en].value
        └── filter_fields()

extract_with_subtable(data)  ← 同时提取子表
  │
  ├── 格式1（旧版 NVD）：data.metrics.cvssMetricV2/V30/V31/V40
  │     ├── 每个版本取 type='Primary' 的第一条
  │     ├── flatten_json() 扁平化，字段名加版本前缀
  │     │   如：metrics_cvssMetricV31_cvssData_baseScore
  │     └── filter_fields() 过滤，返回一条 metrics 记录
  │
  └── 格式2（新版 CVE Record）：data.containers.cna.metrics[]
        ├── 版本键映射：cvssV3_1 → metrics_cvssMetricV31_*
        ├── 扁平化各版本 CVSS 字段
        └── 合并为一条记录
```

#### 3.5 提取结果写入状态

```python
state.update({
    'source':                  'cve',
    'extracted_data':          {...},   # 主表数据
    'extracted_subtable_data': [...],   # 子表数据（CVSS 评分）
    'extraction_confidence':   0.85,
    'is_multi_vuln':           False,
    'vuln_count':              1,
})
```

---

### 第 4 步：clean 节点 — 清洗验证

**位置：** `graph/nodes.py` → `clean_validate_node()` → `agent/cleaner_validator.py`

#### 4.1 数据清洗（DataCleaner）

```
cleaner.clean(extracted_data)
  │
  ├── 遍历每个字段
  │     ├── 字段名含 date/time → clean_date()
  │     │     ├── 解析各种日期格式（ISO8601、中文日期等）
  │     │     └── 统一转为 datetime 对象
  │     ├── 字符串类型 → clean_string()
  │     │     ├── BeautifulSoup 去除 HTML 标签
  │     │     ├── 正则去除多余空白
  │     │     └── 去除控制字符
  │     └── 其他类型 → 原样保留
  │
  └── 返回 cleaned_data
```

#### 4.2 字段验证

```
cleaner.validate(cleaned_data, source)
  │
  ├── 检查必填字段（field_mappings.yaml 中 required: true）
  ├── 检查字段长度（超过 max_length 则截断警告）
  └── 返回 validation_result = {is_valid, missing_fields, warnings}
```

#### 4.3 质量评分

```
cleaner.calculate_quality_score(cleaned_data, validation_result, extraction_confidence)
  │
  ├── 必填字段完整性权重：0.4
  ├── 提取置信度权重：    0.3
  ├── 字段覆盖率权重：    0.3
  └── 返回 quality_score（0.0 ~ 1.0）
```

---

### 第 5 步：check_quality 路由 — 质量门控

**位置：** `graph/builder.py` → `check_quality()`

```
quality_score >= quality_threshold（默认 0.5）
  ├── True  → 路由到 store 节点
  └── False → 路由到 low_quality 节点 → 标记后直接 END
```

---

### 第 6 步：store 节点 — 数据库写入

**位置：** `graph/nodes.py` → `store_node()` → `agent/storage.py` → `database/manager.py`

```
1. HTML 跳过检查（可选）
   skip_html_if_json_processed=True 时：
   检查该漏洞 ID 是否已由 JSON 文件写入 → 已写入则跳过

2. 主表写入（upsert）
   DatabaseManager.upsert(cleaned_data, source='cve')
     ├── 查找 CVEModel（动态生成的 SQLAlchemy 模型，表名 t_cve_main）
     ├── 按 id_field（cveMetadata_cveId）查重
     ├── 存在 → UPDATE（更新所有字段 + modify_time）
     └── 不存在 → INSERT

3. 子表写入（upsert_subtable）
   DatabaseManager.upsert_subtable(cleaned_subtable_data, source='cve')
     ├── 查找 CVESubtableModel（表名 t_cve_metrics）
     └── 每条 CVSS 记录直接 INSERT（一对多关系）
```

---

### 第 7 步：状态返回 + 统计更新

```
final_state = {
    final_status:    'success' / 'failed' / 'low_quality' / 'skipped',
    stored:          True,
    storage_status:  'success',
    end_time:        time.time()
}

controller.update_stats(final_state)
  └── stats['success'] / stats['failed'] / stats['low_quality'] / stats['skipped'] += 1
```

## 四、CVE 漏洞数据处理专项详解

### 4.1 CVE JSON 文件格式

`json/cves/` 目录下的文件格式为 **CVE Record 5.x**，示例结构：

```json
{
  "cveMetadata": {
    "cveId": "CVE-2022-1036",
    "state": "PUBLISHED",
    "assignerOrgId": "...",
    "datePublished": "2022-03-21T00:00:00",
    "dateUpdated": "2022-03-21T00:00:00"
  },
  "dataType": "CVE_RECORD",
  "dataVersion": "5.0",
  "containers": {
    "cna": {
      "title": "漏洞标题",
      "descriptions": [{"lang": "en", "value": "描述内容"}],
      "affected": [{
        "vendor": "厂商名",
        "product": "产品名",
        "cpes": ["cpe:/a:vendor:product:1.0"]
      }],
      "references": [{"url": "https://...", "tags": ["vendor-advisory"]}],
      "metrics": [{
        "cvssV3_1": {
          "baseScore": 7.5,
          "baseSeverity": "HIGH",
          "vectorString": "CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N",
          ...
        }
      }]
    }
  }
}
```

### 4.2 数据源识别规则（为什么能识别为 CVE）

`agent/extractor.py` → `identify_source()`：

| 判断条件 | 结果 |
|---------|------|
| 路径含 `/cves/` | → CVE |
| 文件名以 `CVE-` 开头 | → CVE |
| JSON 内容含 `cveMetadata` 字段 | → CVE |
| JSON 内容含 `containers.cna` 字段 | → CVE |

### 4.3 主表提取详解（extract_cve）

`JSONExtractor.extract_cve(data)` 的完整逻辑：

```
Step 1: flatten_json(data)
  将整个 JSON 树扁平化，嵌套键用下划线连接：
  cveMetadata.cveId         → cveMetadata_cveId
  cveMetadata.datePublished → cveMetadata_datePublished
  containers.cna.title      → containers_cna_title
  ...

Step 2: 特殊字段处理（覆盖扁平化结果）
  ┌─ affected 信息
  │   取 containers.cna.affected[0]
  │   → containers_cna_affected_product
  │   → containers_cna_affected_vendor
  │   → containers_cna_affected_cpes（逗号拼接 cpes 列表）
  │
  ├─ descriptions 合并
  │   所有语言按 en 优先排序
  │   → containers_cna_descriptions_lang = 'en'
  │   → containers_cna_descriptions_value = 'desc1 | desc2'
  │
  └─ references 合并
      所有 URL 用 | 拼接，截断到 512 字符
      → containers_cna_references_url
      所有 tags 合并
      → containers_cna_references_tags
      所有 name 合并
      → containers_cna_references_name

Step 3: filter_fields(flattened, valid_fields)
  只保留 field_mappings.yaml → cve.fields 中定义的字段
  其余扁平化出来的字段全部丢弃
```

### 4.4 子表提取详解（extract_cve_metrics）

`JSONExtractor.extract_cve_metrics(data)` 的完整逻辑：

```
Step 1: 读取 cveMetadata.cveId 作为外键 cve_id

Step 2: 遍历 containers.cna.metrics[]
  每个 metric 可能包含多个版本键：
  cvssV2_0 / cvssV3_0 / cvssV3_1 / cvssV4_0

Step 3: 每个版本独立处理
  flatten_json(cvss_obj, prefix='containers_cna_metrics_cvssV3_1')
  生成字段如：
    containers_cna_metrics_cvssV3_1_baseScore
    containers_cna_metrics_cvssV3_1_baseSeverity
    containers_cna_metrics_cvssV3_1_vectorString
    ...

Step 4: filter_fields(record, valid_subtable_fields)
  只保留 field_mappings.yaml → cve.subtable.fields 中定义的字段

Step 5: 每个版本产生一条记录，追加到 metrics_records 列表
  最终可能有多条记录（如同时有 v3_1 和 v2_0）
```

### 4.5 数据库表结构对应关系

```
CVE 主表：t_cve_main
  ├── cveMetadata_cveId           （主键业务 ID）
  ├── cveMetadata_state
  ├── cveMetadata_datePublished
  ├── cveMetadata_dateUpdated
  ├── containers_cna_title
  ├── containers_cna_affected_product
  ├── containers_cna_affected_vendor
  ├── containers_cna_descriptions_value
  ├── containers_cna_references_url
  └── ... （共 ~40 个字段）

CVE 子表：t_cve_metrics
  ├── cve_id                                   （外键）
  ├── containers_cna_metrics_cvssV3_1_baseScore
  ├── containers_cna_metrics_cvssV3_1_baseSeverity
  ├── containers_cna_metrics_cvssV3_1_vectorString
  ├── containers_cna_metrics_cvssV2_0_baseScore
  └── ... （每个 CVSS 版本各自的字段）
```

### 4.6 完整数据流（以 CVE-2022-1036.json 为例）

```
磁盘文件
D:/json/cves/CVE-2022-1036.json
          │
          ▼
[预过滤] CVE-2022-1036 不在 existing_ids → 继续
          │
          ▼
[extract_node]
  读取文件内容（UTF-8）
  → 识别 source = 'cve'
  → SourceExtractor.extract_from_json()
    → JSONExtractor('cve', cve_config)
      → extract_cve(data)
          flatten_json() → ~200 个扁平字段
          特殊处理 affected/descriptions/references
          filter_fields() → 保留 ~40 个字段
          返回 extracted_data
      → extract_cve_metrics(data)
          遍历 containers.cna.metrics
          flatten + filter
          返回 extracted_subtable_data（1~4 条）
  confidence = 0.85
          │
          ▼
[clean_validate_node]
  DataCleaner.clean(extracted_data)
    日期字段统一格式化
    字符串去 HTML 标签、去多余空白
  validate() → is_valid=True
  quality_score = 0.87
          │
          ▼
[check_quality]
  0.87 >= 0.5 → 路由到 store
          │
          ▼
[store_node]
  DatabaseManager.upsert(cleaned_data, 'cve')
    → t_cve_main INSERT/UPDATE
  DatabaseManager.upsert_subtable(subtable_data, 'cve')
    → t_cve_metrics INSERT
          │
          ▼
final_status = 'success'
```

## 五、关键文件索引

| 文件 | 职责 |
|------|------|
| `main.py` | CLI 入口，参数解析，启动控制器 |
| `graph/controller.py` | 批量调度，预过滤，并发控制 |
| `graph/builder.py` | LangGraph 图结构定义，质量路由 |
| `graph/nodes.py` | 四个节点函数（extract/clean/store/low_quality） |
| `graph/state.py` | 节点间传递的状态对象定义 |
| `agent/extractor.py` | 数据源识别，路由到各 SourceExtractor |
| `agent/json_extractor.py` | CVE/NVD JSON 扁平化提取，子表提取 |
| `agent/cleaner_validator.py` | 字符串清洗，日期格式化，质量评分 |
| `agent/storage.py` | StorageAgent，调用 DatabaseManager 写库 |
| `database/manager.py` | SQLAlchemy 动态模型，upsert 主表/子表 |
| `database/process_tracker.py` | 记录已处理文件（t_processed_files 表） |
| `config/field_mappings.yaml` | 各数据源字段白名单、表名、子表定义 |
| `config/field_config_loader.py` | 读取 field_mappings.yaml 的工具类 |
